# bdd-widget-test (Zed extension)

Zed extension for Flutter developers practicing A-TDD with the
[`bdd_widget_test`](https://pub.dev/packages/bdd_widget_test) package: it brings
the VS Code helper's features to `.feature` files opened in Zed, using the same
TypeScript core under `src/` (so the `bdd_widget_test` naming/resolution
contract stays single-sourced).

The language server is a zero-dependency Node bundle embedded in the extension
(`server/server.cjs`, generated by `npm run build:zed`) and runs on Zed's
bundled Node.js — nothing to install.

## Features

| Feature                                                | VS Code helper | Zed extension                                                                                                                      |
| ------------------------------------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Unresolved-step diagnostics                            | ✅             | ✅                                                                                                                                 |
| Go to definition (step → step `.dart` + function line) | ✅             | ✅                                                                                                                                 |
| "Create step file" quick-fix (scaffolds the file)      | ✅             | ✅                                                                                                                                 |
| Document links on steps                                | ✅             | ❌ Zed has no document-link support ([zed#33587](https://github.com/zed-industries/zed/issues/33587)) — go-to-definition covers it |
| Syntax highlighting / outline / folds / indents        | ✅ (TextMate)  | ✅ (tree-sitter grammar + queries)                                                                                                 |
| "Rebuild step index" command                           | ✅             | n/a (the index is rebuilt on open/save)                                                                                            |

## Install

### Dev extension

```sh
npm install
npm run build:zed        # generates zed/server/server.cjs (required before installing)
```

Then in Zed: `Extensions` → `Install Dev Extension` → select this `zed/` folder.

### Registry

The extension is intended for the [Zed extension registry](https://github.com/zed-industries/extensions)
(not submitted here yet — that needs a public PR against `zed-industries/extensions`).

> **Conflict:** this extension registers the **Gherkin** language. If the
> `gherkin` extension (alameya) is also installed, uninstall one of them so only
> one language server is attached.

## Settings

Zed passes `lsp.bdd-widget-test.settings` straight to the server. The keys are
the same as the VS Code settings (`bddWidgetTestHelper.*`):

```jsonc
// ~/.config/zed/settings.json
{
  "lsp": {
    "bdd-widget-test": {
      "settings": {
        "stepFolderName": "./step",
        "relativeToTestFolder": true,
        "externalSteps": [],
        "showUnresolvedStepWarnings": true,
      },
    },
  },
}
```

To use a custom binary instead of the embedded server:

```jsonc
{
  "lsp": {
    "bdd-widget-test": {
      "binary": { "path": "/path/to/server", "arguments": ["--stdio"] },
    },
  },
}
```

`bdd_options.yaml` / `build.yaml` options still take precedence over these
settings, exactly as in the VS Code helper.

## Build

```sh
npm run build:zed    # tsc type-check + esbuild → zed/server/server.cjs
```

`zed/server/server.cjs` is generated but committed (the registry installs from
the repo and the Rust shim `include_str!`s it). Do not edit it by hand.

## Not implemented

- Document links (Zed API limitation, see the table above).
- "Rebuild step index" command: the server rebuilds the index whenever a
  `.feature` file is opened or saved. Step files created outside the editor are
  picked up on the next open/save (no file watcher).
